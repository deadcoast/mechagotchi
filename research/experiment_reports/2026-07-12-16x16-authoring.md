# Experiment Report: 16×16 Authoring End to End (Cycle 18 · WORKSHOP · H1)

Date: 2026-07-12

## WHY

The gap table's Workshop row and a standing cross-track remainder:
the editor gained a 16×16 canvas in cycle 09 and the server's release
path has always been engine-validated — but no 16×16 creature had
ever been AUTHORED AND RELEASED, so the committed release corpus held
only 8×8-era pieces and every game-era admission of workshop content
rejected on size coherence. Real Contribute/pack value was blocked on
this.

## WHAT

**The pin first (RED)**: a game-side test demanding at least one
committed, release-marked 16×16 creature that a game era ADMITS and
that LEADS the founder pool — failing with "no 16x16 creature in
data/workshop/released — the authoring gap stands."

**The authoring act, through the REAL pipeline** (nothing
hand-stamped): a NEW creature — the *glow lantern* — authored as an
editor token matrix (body/eyes/anchor/mouth on the 16×16 canvas),
compiled by the server's own `_build_grid`, judged by the engine's
validator (valid) and the LCD covenant's alignment (aligned), and
released through `release_creature` — the same function the editor's
release button calls, which re-validates at release time and stamps
the `released_into_ecosystem` lineage mark. The released file is the
committed fixture: `data/workshop/released/released_glow_lantern.json`.

**The pin, GREEN**: the lantern loads with the release mark, a game
era ADMITS it through the F9 gates, it LEADS the founder pool, and
the era survives.

**The corpus's truth changed, and its dependents updated honestly**:
the two F9-era tests that pinned "exactly two releases / all
rejected" now pin the richer truth (three releases; the lantern
admits; the 8×8 pair still rejects verbatim on size — kept as the
honest rejection fixtures); the F9 evidence builder's positional
assumption was replaced with id-based assertions; all fifteen
`data/game_client/` artifacts regenerated, every status `complete`
(the starter pack now carries the lantern too).

## HONEST REMAINDER

1. **The lantern was authored by script against the server's own
   compile/release functions**, not by mouse in the browser — the
   functions ARE the editor's path (the page posts to them), but a
   human-driven browser session remains the H5 first-session gate's
   territory.
2. **The 8×8 pieces stay committed on purpose** — they are the
   rejection-path fixtures the F9/F16 suites pin.
3. **Editor ergonomics at 16×16** (zoom, denser tooling) are H2–H3
   territory; H1 proves the pipeline, not the polish.

# Windows delivery and native entry

Application packaging and interaction adapters; no scientific model or adoption.
The supported complete player is Windows x64 one-directory delivery. The EXE,
adjacent _internal payload and artifact manifest travel together. Source checkouts
remain a developer form; an arbitrary installed wheel does not inherit checkout
resources. Frozen resolution uses its exact bundle root, never an ancestor.

The runtime manifest pins explicit weather, covenant, grid, model, Workshop helper,
page, schema and notice files. The artifact manifest hashes the built distribution.
Both retain source HEAD and dirty state; neither is a signature or proof of cloud CI.
The installed helper closure must be exercised in the actual detached artifact.

startup.inspect_home reads primary and backup independently without writes or
default asset discovery. Its immutable inspection binds later explicit Resume,
Restore and New to the reviewed bytes. Recovery rechecks captured bytes inside
the existing session authority. Invalid and absent files differ; inspection does
not establish writability. New resolves defaults only after the player's choice.
Existing originals survive recovery and replacement. Confirmations start on Cancel
and disarm through redraw/key release; cancel creates no Keeper files.

native_ui owns focus and integer-scale geometry, entry owns startup choices,
app owns existing action routes and care. Contextual controls do not create engine
actions. Source-event, API, staged import, detached executable, OS keyboard and
human usability evidence remain separate. Examples use exclusive new directories
and actual public engine/application calls; toy inputs are not calibration evidence.

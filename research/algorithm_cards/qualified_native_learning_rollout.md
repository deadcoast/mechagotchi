# Qualified native learning rollout

## Name

Native New policy resolution over source-bound product learning evidence.

## Purpose

Make qualified per-life learning available by default for built-in fresh native
Keepers while preserving saved policy, historical experiment semantics and a
visible incumbent choice.

## Mathematical basis

Existing full-confidence Q-table follower, unchanged. Admission uses the completed
product cohort's exact sums of six-decimal per-life requested-horizon welfare:
(follower-baseline)*100 >= 5*baseline against BOTH incumbent and additive. No new
reward, confidence, survival definition or causal care selector is introduced.

## Inputs

Native entry's exact primary/backup inspection, optional requested policy and
whether both input options were omitted. The historical study used 50 admitted
hatched 16x16 founders, exact cleanliness covenant, five synthetic keepers,
100 lives each, 200 ticks and the original paired seeds.

## Outputs

Explicit policy if selected; prior-policy continuity when either snapshot is
valid; otherwise qtable for built-in inputs or incumbent for custom inputs.
Native confirmation allows a New-only policy override. Low-level omitted helper
and constructor defaults remain incumbent. Newborn tables are cold.

## Strengths

All1500 receipts and source/input bindings independently validated; gains exceed
both unchanged 5% thresholds. The native path has bounded process receipts,
conflict/no-write checks, real starvation/succession and exact warm continuation.

## Weaknesses

Synthetic Keepers and one covenant do not establish human tolerance or a custom
covenant benefit. Follower has more begs/feeds ; 400 nonattentive lives die per arm.
One attentive follower life dies while both comparators survive. No universal
per-life improvement, attachment, personality or biological inheritance is shown.

## Failure modes

Applying a new default during resume would overwrite saved authority; changing
the constructor default would migrate historical studies; changing tables during
succession would fabricate learning inheritance. These paths are explicitly tested.
The retained first verifier failed by assuming preparation paused care; its
corrected exact-continuation check changes no product behavior or scientific gate.

## Integration risk

Final packaged delivery and aggregate checks remain separate from source acceptance.
Native policy display must use prior authority when a valid snapshot exists, and
only an explicit New toggle may override it. Care-selection v2 and X8 are separate.

## License status

Repository Apache-2.0; no dependency or external asset added.

## Prototype result

Source implementation passes 14 rollout tests, 20 startup tests and 4 native-entry
tests. Corrected source process verifier passes 16 checks / 12 launches in 8.0974345 seconds.
Failed first verifier is retained; cumulative 16.0605437 seconds. Scientific prior evidence
is ADOPT (+11.7106982904%/+12.0719905870%); DR0066 remains historical REFUSE.

## Decision

Adopt only qualified fresh native built-in default and explicit New-only choice;
keep native release/full verification distinct and retain all historical findings.

## Go-No-Go gate

Valid prior science against both comparators, cold new lives, exact current-life
restart, unchanged no-care dependence, preserved save authority and conflicts,
custom-context incumbent fallback, terminal-free opt-out, then fresh bundle and
final aggregate/artifact/preservation review. Missing release evidence is not green.

## Dated independent review repair (2026-10-06)

Exception-driven refresh after a stale save inspection now recomputes New's
displayed effective policy from the freshly inspected primary/backup. The new
event regression failed in both policy directions before repair and passes after,
with unchanged external save bytes on refusal. Current focused coverage is 48
tests, including 15 rollout tests. Prior stage0/process observations remain dated
snapshots; the final bundle verifier must bind this correction.

## Question and authority

cleanliness by default. Compare the existing LCD covenant with Q2's validated
v0.2 cleanliness covenant on the actual default 16x16 creature. No scientific
parameter, reward definition, danger threshold or Q-table default changes.

and new campaigns. This is a hypothesis that the historical regeneration set
can be empty, not permission to relabel old evidence as the new default.

## Gates written before measurement

1. Reproduce the committed companion-loop metrics at its documented 400-tick
   budget and DR 0059's full metrics/decision before judging a candidate.
2. On the candidate, the existing attentive beg-answering keeper survives
   the same 400 ticks. The neglected companion retains the incumbent death
   age and cause. These are existing survival claims, not invented tolerances.
3. A 72-tick scripted keeper follows the existing health binding word
   (hungry->feed, tired->sleep, lonely/stressed->play), and cleans when at
   least one clean action's restore has been lost. The threshold is derived
   as 1 - CLEANLINESS_RESTORE, never retuned after the run. It must survive,
   perform a clean action and increase cleanliness when cleaning.
4. A real SDL headless window must display the engine cleanliness value and
   G clean within the default window width, route G, save the choice and
   resume the same life. Existing saves retain their stored profile/state.
5. Product session defaults, new campaign defaults and bundled assets must
   name the same validated covenant. A supplied companion covenant must also
   seed a NEW campaign; a resumed campaign retains its recorded covenant.
6. Every incumbent data artifact remains byte-identical. Current-default
   claims live in new Q3 artifacts. Enumerate actual source bindings and the
   exact new/unchanged artifact set in the report. Do not regenerate studies
   under a changed meaning. Rebuild/test the local Windows bundle separately.

ADOPT only when all candidate acceptance checks (1-4) pass. Otherwise REFUSE,
record the measured reason, and keep the old product default. Landing checks
5-6, full regression verification and the actual release smoke test must pass
before calling an adopted default shipped locally. Human usability remains
unmeasured; the scripted/geometry checks do not substitute for it.

## Cohesive application corrections

The window currently creates its evolution bench independently of --slip or a
resumed companion's covenant. Correct that mismatch for a new campaign while
preserving existing campaign state. Expose --slip and --keeper-dir through
the existing mechas game launcher so authored examples are reachable without
bypassing the product entry point. Preserve argument-vector subprocess calls,
validate conflicting operations, and do not overwrite existing saves silently.

The minimum slice is game defaults/campaign continuity, launcher examples,
the scientific decision with portable evidence, and a tested built executable.
No unrelated visual redesign, background service or remote publication.
